# 加字段 + 配套查询接口

适用场景：给已有模块加一个新字段（含数据库列），并加一个基于这个字段的查询接口。

## 走哪个通道

这类需求几乎总是超过 Vibe 的"步数 ≤ 2 且单文件"标准：至少涉及 model、迁移、service、接口层，通常是 3 个以上文件。默认走 **Spec 产线**：

```
/flow 给 <模块> 加 <字段> 字段和按它查询的接口
```

只有当字段和查询逻辑极其简单、且确定只改一个文件（比如只是给已有的通用查询方法加一个可选参数，不涉及新增列）时，才可能落进 Vibe，但这种情况少见，拿不准就走产线。

## 准备

- 明确字段的类型、是否可为空、默认值、长度限制——这些没说清楚就是 `/flow-propose` 里的未决问题，不要自己猜。
- 明确查询接口的形态：精确匹配还是模糊匹配、是否需要分页、和现有查询接口是合并还是新开一个。
- 找到模块现有的"加字段"或"加查询接口"的历史改动作参考（如果有），照着现有模式改，不要另起一套风格。
- 确认迁移文件的写法和执行方式（本仓库用什么迁移工具、命名规则）。

## 提示词模板

```
给 <模块> 加一个 <字段名> 字段，并加一个按 <字段名> 查询的接口。只改必要的代码。

背景：
- 字段类型：<类型，是否可空，默认值>
- 查询方式：<精确匹配 / 模糊匹配 / 是否分页>
- 参考：<如果有类似的历史改动，给出 file:line 或变更目录>

要求：
- 改动范围只包括：数据模型、迁移文件、service 层、接口层，以及这几处对应的测试
- 不要顺手重构无关代码，不要改动不相关的字段或接口
- 新增的字段、接口、迁移语句里，涉及的每个已有字段名/表名先去源码确认存在，不要凭字段命名习惯猜
- 给出改动文件清单和每个文件改了什么
```

## 期望产出

- 迁移文件：新增列，带类型、默认值、是否可空。
- 数据模型：新增字段定义，序列化/反序列化如果需要特殊处理要说明。
- service 层：写入路径支持新字段；新增按该字段查询的方法。
- 接口层：新增或扩展查询接口，包含入参校验。
- 测试：覆盖"写入后能查到""字段为空时查询行为""非法输入"这几种场景。
- 一份改动文件清单，逐条说明改了什么、为什么。

## 验收

- 迁移文件能在本地环境跑通（up 和 down 都验证）。
- 跑通新增/修改的测试，报告实际输出，不是"应该没问题"。
- 用真实请求验证一次新接口的查询结果（本地或测试环境）。
- 对照改动文件清单，逐个确认没有超出清单之外的文件被改动。
- 检查新接口的入参校验：空值、超长、非法字符是否有处理。

## 常见翻车

- **凭空发明字段名或表名**：比如以为存在 `order_note` 字段，实际叫 `remark`。要求先去源码确认已有命名。
- **顺手改了无关代码**：比如顺便把旁边一个函数重构了。提示词模板明确限定改动范围。
- **迁移文件忘了写 down 或者默认值和业务预期不符**：验收阶段专门跑一次 down。
- **新查询接口没做分页或者没做权限校验，抄错了参考实现**：准备阶段先确认查询形态，验收阶段单独检查校验逻辑。
- **测试只测试了"正常写入正常查询"，没测空值和边界**：期望产出里明确列出要覆盖的场景。

## 示例

需求：给订单加 `remark`（备注）字段，支持按备注模糊查询。

```
给订单模块加一个 remark 字段，并加一个按 remark 查询的接口。只改必要的代码。

背景：
- 字段类型：string，可空，默认空字符串，长度上限 500
- 查询方式：模糊匹配（LIKE），需要分页，参考现有的 ListOrders 分页参数
- 参考：internal/order/service.go:80 的 ListOrders 方法

要求：
- 改动范围只包括：数据模型、迁移文件、service 层、接口层，以及这几处对应的测试
- 不要顺手重构无关代码，不要改动不相关的字段或接口
- 新增的字段、接口、迁移语句里，涉及的每个已有字段名/表名先去源码确认存在，不要凭字段命名习惯猜
- 给出改动文件清单和每个文件改了什么
```

产出应包括：`migrations/xxxx_add_remark_to_orders.sql`（加列，`VARCHAR(500) DEFAULT ''`）、`internal/order/model.go` 加 `Remark` 字段、`internal/order/service.go` 新增 `ListOrdersByRemark` 方法（复用现有分页逻辑）、接口层新增路由，以及对应的单元测试。验收时跑一次迁移 up/down，跑测试，再用一个真实带 remark 的订单验证查询结果。
